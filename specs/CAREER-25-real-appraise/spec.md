## 문제
결과 카드의 아저씨 값과 대사가 늘 같은 가짜(`{ mochi: 3, … }`)라서 사진이 무엇이든 감정이 똑같다. 진짜 AI를 붙이면 새로 생기는 일 셋 — 실패하면 아저씨가 '갸웃'에서 멈추는 것, 말투·값이 흔들리는 것(꽃 거절 · 같은 사진인데 값이 다름 · 사람 가리키는 말, 프롬프트 v2 말맛 시험에서 남은 문제), 호출 한 건마다 돈이 드는 것 — 을 아직 아무도 확인할 수 없다.

## 정해진 것 (사용자 결정)
- 10/21: AI 호출 구조 B — 브라우저 → CloudFront → v1 프라이빗 EC2(`api/`) → bedrock-runtime 인터페이스 VPC 엔드포인트 → Nova Pro(`apac.amazon.nova-pro-v1:0`). 감정 1건 약 3원
- 10/21: 사진이 다른 아시아 리전에서 처리될 수 있다(`apac.` 리전 간 추론) → 화면에 안내 한 줄(화면 연결 때, 아래 A)
- 서버 입구 약속(사진 받는 법 · 크기 상한 · HTTP 응답 · 실패 코드)은 CAREER-26과 함께 쓰고, 모양은 architect가 `contracts/`에서 정한다. 이 스펙은 필요한 것만 적는다
- 화면 쪽 감정 함수 모양은 [contracts/appraise.md](../../contracts/appraise.md)(확정) 그대로다 — 입력 `{ photo, myPrice, tags }` · 출력 `{ mochi, line }` · 실패 `Error.code` `daily_limit` · `invalid_input` · `unavailable`

### 서버 (`api/`)
- AC-1 서버가 Nova Pro를 불러 `{ mochi, line }`을 돌려준다
  - 주어진: Bedrock 클라이언트를 가짜로 바꾼 `api/` 테스트, 가짜는 정상 모양의 모델 출력(등급 1~5 중 하나 + 대사)을 돌려준다
  - 할 때: 올바른 입력(사진 · `myPrice` · `tags`)으로 감정 입구를 부른다
  - 그러면: Bedrock 호출이 정확히 1번이고 모델 id가 `apac.amazon.nova-pro-v1:0`이다. 모델 id는 설정 한 곳에만 있다(`api/` 안에서 이 문자열을 grep하면 한 곳). 응답은 키가 `mochi`·`line` 둘뿐이고, `mochi`는 가짜가 고른 등급에 서버 표가 매긴 값과 같으며(등급 1~5 다섯 경우 모두), `line`은 공백만이 아니며 30자 이하다. 등급→모찌 표는 `api/` 안 한 곳에만 있다
- AC-2 서버는 브라우저가 보낸 값을 믿지 않는다
  - 주어진: AC-1과 같은 테스트
  - 할 때: (a) 모르는 `myPrice` (b) 모르는 태그 id (c) 같은 태그 두 번 (d) 태그 17개 (e) JPEG가 아닌 파일(PNG · 이미지가 아닌 것) (f) 서버 바이트 상한 1MB를 1바이트 넘는 JPEG (g) 위치 정보(EXIF GPS)가 담긴 JPEG (h) 긴 변이 1024px를 넘는(1025px) JPEG로 부른다
  - 그러면: 여덟 경우 모두 `invalid_input`으로 끝나고 Bedrock 호출은 0번이다 (contracts/appraise.md §7). 상한과 정확히 같은 크기의 JPEG, 긴 변이 정확히 1024px인 JPEG(10/21 사용자 승인 — contracts/appraise-http.md §3-4), GPS 없이 다른 EXIF만 든 JPEG는 통과한다(Bedrock 호출 1번). 1MB를 몇 바이트로 세는지는 contracts에 적힌 값을 따른다
- AC-3 AI 출력이 정해진 모양이 아니면 `unavailable`이다 — 빈 성공으로 바꾸지 않는다
  - 주어진: 가짜 Bedrock이 (a) JSON이 아닌 글 (b) 등급 없음 (c) 등급이 1~5 밖·소수·문자열 (d) `line`이 빈 문자열 (e) `line`이 31자 (f) contracts에서 정한 출력 길이 상한을 넘는 글을 돌려준다
  - 할 때: 감정 입구를 부른다
  - 그러면: 여섯 경우 모두 `unavailable`이고, 로그에 어느 검사에서 왜 실패했는지 이름이 한 줄 남는다 (`docs/reference/` §4)
- AC-4 일시 오류만 다시 시도한다
  - 주어진: 가짜 Bedrock이 (a) 요청 수 초과(Throttling) (b) 5xx (c) 연결 끊김을 계속 돌려준다 / (d) AccessDenied (e) ValidationException을 돌려준다
  - 할 때: 감정 입구를 부른다
  - 그러면: (a)~(c)는 Bedrock 호출 수가 '1 + 설정의 재시도 횟수'와 같고 마지막에 `unavailable`이다. (d)(e)는 호출 1번 뒤 바로 `unavailable`이다. 재시도 횟수는 설정 한 곳에서 읽는다 (`docs/reference/` §1)
- AC-5 서버가 무한정 기다리지 않는다
  - 주어진: 가짜 Bedrock이 응답하지 않는다(가짜 시계)
  - 할 때: 감정 입구를 부른다
  - 그러면: 설정의 시간 제한이 지나면 `unavailable`로 끝난다
- AC-6 호출 기록이 남고, 사진과 비밀값은 남지 않는다
  - 주어진: AC-1 · AC-3 · AC-4의 테스트에서 로그 출력을 모은다
  - 할 때: 모은 로그를 본다
  - 그러면: 감정 요청 1건마다 결과 종류(성공 · 실패 코드) · 걸린 시간 · 입력/출력 토큰 수가 든 줄이 1줄 있고, 사진 바이트(base64 포함)와 AWS 자격 증명 값은 0번 나온다

- **AI 호출이 생긴다** — 처음으로 과금 경로가 열린다. 감정 1건 약 3원 × (1 + 재시도 횟수)까지. 이번엔 공개 입구가 없어(결정 B) 호출은 로컬 서버와 시험 실행에서만 생긴다
- **새 입구** — 서버 감정 입구(사진을 받는다), 로컬에서만 뜬다. JPEG만 · 1MB 상한 · GPS 담긴 사진 거절(AC-2). 모양은 CAREER-26과 함께 contracts에서
- **새 인프라 리소스** — `culonculon/aws-infra-portfolio`에 bedrock-runtime 인터페이스 VPC 엔드포인트(시간당 요금 + 처리 GB 요금, AZ 수만큼) · 보안 그룹 · EC2 IAM 정책. 요금은 사용자가 apply한 뒤부터
- **시험 세트 실행** — 사진 약 10장 × K번 ≈ 10K건(K=3이면 약 30건 ≈ 90원)/회. 프롬프트를 고칠 때마다 다시 돈다
- **넓은 자격 증명 사용** — 시험 실행은 사용자 컴퓨터의 terraform-admin 자격 증명으로 돈다(결정 C). 시험 실행 명령이 Bedrock 호출 말고 다른 AWS 호출을 하지 않는지, 자격 증명 값이 로그·결과 파일에 남지 않는지 볼 것
- 사진이 `apac.` 리전 간 추론으로 서울 밖 아시아 리전에서 처리될 수 있다(시험 세트 사진 포함. 화면 안내는 화면 연결 때)
