## 문제
서버(CAREER-25)와 사진 보내기(CAREER-26)는 각각 테스트로만 확인됐고, 로컬 화면에서 '감정 받기'를 누르면 아직 결과 카드 대신 실패 문구가 나온다(Vite가 `/api/appraise`를 모름). 그래서 사용자는 비용 상한(CAREER-27)과 배포 전에 진짜 아저씨 감정을 한 번도 눈으로 보지 못했고, 사진이 서울 밖 아시아 리전에서 처리될 수 있다는 사실(ADR-0002)도 화면에서 알리지 않는다.

## 근거와 이 스펙이 둔 가정
- 근거: CAREER-25 결정 A·B · CAREER-26 plan S1(실패 화면은 26에서 이미 함)·S4(이 스토리 제안)·'질문 7 답' · contracts/appraise-http.md §1(로컬은 Vite dev 프록시 `/api` → `http://127.0.0.1:8787`, CORS 없음) · contracts/appraise.md §5(리전 안내 문구)
- Jira 설명은 이 세션에서 직접 열지 못해(Atlassian 도구 권한 없음) 사용자가 옮겨 준 글을 따랐다.
- 가정 1: '진짜 감정 서버'는 `api/`를 고치지 않고 `npm --prefix api start`로 띄운 그대로다(포트 8787 기본값). `PORT`를 바꿔 띄우는 경우는 다루지 않는다.
- 가정 2: `app/vite.config.js`에는 지금 `test:` 블록이 없지만, 따로 된 vitest 설정 파일이 없어 vitest가 이 파일을 읽는다. 그래서 "vitest 설정과 같은 파일이라 사람이 보고 승인"(CAREER-25 plan 실패 시나리오 20)을 그대로 따른다.
- 가정 3: 서버가 꺼져 있을 때 Vite 프록시는 JSON이 아닌 오류 응답을 주고, 어댑터는 이것을 `unavailable`로 바꾼다(appraise-http.md §5 '어댑터 규칙'). 그래서 AC-3은 새 화면이 아니라 **연결 뒤에도 26의 실패 처리가 그대로 도는지** 확인하는 조건이다.
- 가정 4: 화면은 지금처럼 `127.0.0.1`(Vite 기본)에서만 뜬다. 같은 네트워크의 다른 기기(휴대폰)에서 여는 일은 사용자 질문 U3에 따른다.

## 비용·남용 영향
- **AI 호출**: 화면에서 진짜 Bedrock을 부르는 길이 처음 생긴다(로컬에서만). 이번 스토리의 호출은 AC-1·AC-3 사람 확인 몇 건뿐 — 감정 1건 약 3원 × 최대 3번(재시도 포함, appraise-http.md §8). 같은 사진·같은 태그를 다시 누르면 서버 기억으로 0번(CAREER-25 AC-17). 호출 수는 PR '비용·남용 영향' 칸에 적는다(AC-1)
- **새 입구**: 없음 — `api/` 입구는 CAREER-25 그대로다. 다만 dev 서버 프록시가 그 입구로 가는 **새 길**이 된다. dev 서버가 `127.0.0.1`에만 묶여 있는 동안은 이 컴퓨터 밖에서 닿지 않는다. dev 서버를 네트워크에 열면(`--host`) 같은 네트워크의 누구나 비용 상한 없이 Bedrock을 부를 수 있다 → '안 할 것'과 질문 U3
- **테스트 중 과금 위험**: 사용자 컴퓨터에서 api가 떠 있는 채로 e2e를 돌리면, 가로채기를 놓친 요청이 프록시로 진짜 서버까지 간다 → AC-5로 막는다. CI에는 api 서버가 없어 과금이 없다
- **자격 증명**: AC-1을 위해 api 서버가 AWS 자격 증명을 들고 사용자 컴퓨터에서 뜬다. 세션은 로컬 AWS 자격 증명을 쓰지 않는다(CLAUDE.md §6) — 누가 띄우는지는 질문 U1
- 새 인프라 리소스: 없음
- 사진: 브라우저를 거쳐 EXIF가 지워진 1024px JPEG만 나간다(CAREER-26). `apac.` 리전 간 추론으로 서울 밖에서 처리될 수 있음을 AC-2로 화면에 알린다
