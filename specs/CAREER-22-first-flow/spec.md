## 문제
앱에 시작 화면 한 장("how-much")만 있어서, 사진 → 마음 가격·사연 태그 → 아저씨 감정 → 결과 카드라는 핵심 재미를 아무도 끝까지 해 볼 수 없다. 나중에 진짜 AI로 갈아 끼울 감정 자리(`{"mochi": 정수, "line": "한 줄"}`)도 아직 없다.

## 완료 조건
<!-- 모두 로컬 개발 서버 + 브라우저에서 확인한다. "아저씨 자리"는 화면 가운데 도트 아저씨가 들어갈 자리(이번엔 그림 대신 자리 표시)를 말한다. -->
- AC-1 사진을 고른다
  - 주어진: 개발 서버로 연 첫 화면
  - 할 때: 사진 고르기에서 이미지 파일(jpg 또는 png) 하나를 고른다
  - 그러면: 고른 사진의 미리보기가 화면에 보인다
- AC-2 이미지가 아닌 파일은 받지 않는다
  - 주어진: 첫 화면
  - 할 때: 이미지가 아닌 파일(예: `.txt`)을 고른다
  - 그러면: 미리보기가 나오지 않고, 사진을 다시 고르라는 안내 문구가 보이며, '감정 받기' 버튼은 눌리지 않는다
- AC-3 마음 가격은 버튼 4개 중 하나만
  - 주어진: 첫 화면
  - 할 때: 마음 가격 버튼을 본 뒤 하나를 누르고, 다른 하나를 다시 누른다
  - 그러면: 버튼은 정확히 4개(🍡1개 · 10개 · 100개 · 🙅안 팔아)이고, 마지막에 누른 버튼 하나만 선택됨으로 보인다. 선택됨은 눈으로도, 보조기술로도(예: `aria-pressed="true"`) 확인된다
- AC-4 사연 태그는 4묶음 16개
  - 주어진: 첫 화면
  - 할 때: 사연 태그를 본 뒤 서로 다른 태그 둘을 누르고, 그중 하나를 다시 누른다
  - 그러면: 묶음 제목 4개(어떻게 왔나 · 지금 상태 · 마음 · 자랑) 아래 태그가 6 · 4 · 4 · 2개, 합쳐 16개 있고(이름은 설계 메모 그대로), 두 번 누른 태그는 선택이 풀리고 나머지 하나만 선택됨으로 남는다 (여러 개 고를 수 있고 0개도 된다 — 10/21 사용자 결정)
- AC-5 자유 글을 받지 않는다
  - 주어진: 첫 화면부터 결과 카드까지 모든 화면
  - 할 때: 입력칸을 찾는다
  - 그러면: 글을 칠 수 있는 칸(`textarea`, 텍스트·숫자 `input`, `contenteditable`)이 하나도 없다
- AC-6 다 고르기 전에는 감정을 못 받는다
  - 주어진: 첫 화면
  - 할 때: (a) 아무것도 안 고른 상태 (b) 사진만 고른 상태 (c) 마음 가격만 고른 상태에서 '감정 받기'를 본다
  - 그러면: 세 경우 모두 '감정 받기' 버튼이 비활성이다. 사진과 마음 가격을 둘 다 고르면 활성이 된다 (사연 태그는 0개여도 된다)
- AC-7 감정 중에는 아저씨가 갸웃한다
  - 주어진: 사진과 마음 가격을 고른 상태
  - 할 때: '감정 받기'를 누른다
  - 그러면: 결과 카드가 나오기 전에 아저씨 자리에 '갸웃'(🔍) 상태가 보이고, 그동안 '감정 받기'는 비활성이라 다시 누를 수 없다 (한 번 누르면 감정은 한 번만 불린다 — 단위 테스트로 호출 횟수 1을 확인)
- AC-8 결과 카드가 나온다
  - 주어진: AC-7에서 감정이 끝난 뒤
  - 할 때: 화면을 본다
  - 그러면: 아저씨 자리가 '도장'(🔨) 상태로 바뀌고, 결과 카드에 (1) 아저씨 값 "모찌 N개"(N은 0 이상 정수) (2) 내가 고른 마음 가격(예: "모찌 10개" 또는 "안 팔아") (3) 비어 있지 않은 아저씨 한 줄 대사가 함께 보인다
- AC-9 가짜 감정 함수가 진짜와 같은 모양을 돌려준다
  - 주어진: 가짜 감정 함수
  - 할 때: 단위 테스트에서 마음 가격 4가지 각각과 태그 0개·여러 개로 부른다
  - 그러면: 매번 `{ mochi, line }` 모양으로 끝나고, `mochi`는 0 이상 정수, `line`은 비어 있지 않은 문자열이며, 다른 키는 없다. 화면은 이 함수를 한 곳에서만 부른다(갈아 끼울 자리가 하나)
- AC-10 사진이 브라우저 밖으로 나가지 않는다
  - 주어진: AC-1 → AC-8을 한 번 끝까지 도는 e2e
  - 할 때: 그동안 브라우저가 보낸 요청을 모은다
  - 그러면: 개발 서버(로컬) 밖으로 나간 요청이 0개이고, 고른 사진 파일을 담은 요청도 0개다
- AC-11 끝까지 한 번이 자동으로 확인된다
  - 주어진: `e2e/`의 Playwright 테스트와, 사용자가 채운 `pipeline.config.json`의 `checks.app.e2e`
  - 할 때: 저장소 루트에서 `checks.app.e2e`를 그대로 돌린다
  - 그러면: AC-1 · AC-3 · AC-4 · AC-6 · AC-7 · AC-8 · AC-10을 한 흐름으로 지나는 테스트가 1개 이상 통과하고 종료 코드 0으로 끝난다 (0개 통과로 끝나지 않는다). 기존 `lint` · `test` · `build`도 종료 코드 0이다
- AC-12 e2e가 실패를 잡는다
  - 주어진: AC-11이 통과하는 상태
  - 할 때: 결과 카드에 아저씨 한 줄 대사가 안 나오게 일부러 바꾸고 `checks.app.e2e`를 돌린다
  - 그러면: 종료 코드가 0이 아니다 (확인 뒤 되돌리고, 결과는 세션 보고에 출력 그대로 적는다)

## 안 할 것
- 진짜 AI 호출(Bedrock Nova Pro) — 나중 스토리. 화면에서 AI나 외부 서버를 직접 부르는 경로도 만들지 않는다(AI 호출은 `api/`를 거친다, CLAUDE.md §9)
- 서버 · `api/` · 사진 업로드 · 사진이나 결과 저장
- 공유(공유 카드·링크·이미지 내보내기)
- 비용 상한 · 아저씨 '퇴근' 상태
- 안전 거르기(사진 내용 검사 등)
- 사진 줄이기(브라우저에서 리사이즈)·위치 정보(EXIF) 지우기 — 업로드가 생기는 스토리로 넘김(10/21 사용자 결정)
- 진짜 도트 그림 · 애니메이션 — 아저씨 자리는 자리 표시와 상태 이름(갸웃·도장)만
- 다시 감정하기 · 처음으로 돌아가기 흐름 — '한 번 끝까지'만
- 아저씨 상태 추가, 환율 교체(붕어빵 등), 자랑 벽, 친구 맞히기, 랭킹, 광고 (11/8 범위 밖)
- `infra/` · 배포 · CI에서 e2e 돌리기(열린 질문 4)

## 비용·남용 영향
없음 — AI 호출 없음(가짜 함수), 새 입구(엔드포인트·업로드) 없음(사진은 브라우저 안에서 미리보기만, AC-10으로 확인), 새 인프라 리소스 없음.
다만 AC-9의 `{ mochi, line }` 모양과 AC-7의 '감정 중 다시 못 누름'은 진짜 AI로 갈아 끼울 때 그대로 이어져 요청 수에 영향을 준다. 새 npm 의존성(Playwright 등)은 PR '새 의존성'·'결정' 칸에 적는다.
