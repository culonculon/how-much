## 문제
밖 주소를 iPhone Safari로 연 사람은 글자와 이모지뿐인 입력 폼을 보게 되어, '동네 감정소에 물건을 들고 가 아저씨에게 값을 듣는' 재미를 느끼지 못한다.

## 근거와 이 스펙이 둔 가정
- 근거: Jira CAREER-35(사용자가 옮겨 줌, 11/1 승인) · [시안 mockup-v3.html](mockup-v3.html) · [contracts/appraise.md](../../contracts/appraise.md) §3·§5 · [ADR-0008](../../docs/adr/0008-screens-without-url-change.md) · [CAREER-32 spec](../CAREER-32-reappraise-card/spec.md) · `app/src/App.jsx` · `app/src/options.js`
- 이 세션은 Jira를 열지 않았다. '문제' 줄은 Jira 글에서 읽어 낸 것이라 사용자 확인이 필요하다
- 가정 1: 시안은 **모양**의 원본이다. 태그는 7개만, 값 칩은 바쁨 화면에 1개만 그려져 있는데 예시로 본다. 화면에는 contracts §3 그대로 16개 태그 · 4묶음 · 원래 이름, 값 칩 4개가 다 나온다
- 가정 2: 시안의 '흠… 귀한 물건이군!'과 `× 30`은 예시다. ⑥ 대사는 서버가 준 `line`, 값은 서버가 준 `mochi`다
- 가정 3: 시안의 설명 글 '공유 버튼 없음' · '(사진을 못 읽었을 때만 보임)'은 화면에 넣지 않는다. '고른 사진·사연·값은 그대로 남아 있어요'는 unavailable 화면에 넣는다
- 가정 4: ⑥ 값은 시안대로 `🍡 × N`으로 보이고, 화면 읽기로는 `모찌 N개`로 읽힌다. 내가 부른 값도 같은 모양이고 `never`는 `안 팔아`다
- 가정 5: ③ 건너뛰기는 따로 버튼을 두지 않는다. 태그를 안 고르고 '다음 ▶'을 누르면 된다(시안 · contracts §2 태그 0개 허용)
- 가정 6: 시안 ① 간판 `HOW-MUCH`는 지금 제목(`how-much`)을 옮긴 것으로 본다. 새 이름을 정하는 일이 아니다(Jira '안 넣을 것: 서비스 이름')
- 가정 7: 새로고침 · 바로 열기는 CAREER-32 가정 5를 잇는다. 고른 것을 되살리지 않고(사진 보관 안 함) 빈 ①에서 시작한다
- 가정 8: `BUSY_TEXT`는 Jira에 'contracts 그대로'로 묶여 있지만 실제로는 contracts에 없고 `options.js`에만 있다(CAREER-32 plan A1). 이 스펙에서는 `options.js` 값을 원본으로 본다

## 완료 조건
<!-- AC-1~11은 가짜 감정 응답으로 로컬에서 자동 확인(진짜 Bedrock 0번). AC-12는 배포 뒤 사람이 iPhone으로 확인. '추천안 기준'이라 적힌 AC는 해당 Q의 답이 다르면 승인 전에 고친다. -->
- AC-1 6단계가 차례로, 한 번에 하나씩 나온다
  - 주어진: `appraise`를 가짜로 바꿔 `모찌 30개`로 답하게 하고(답은 테스트가 풀어 줄 때까지 기다림), 처음 연 화면
  - 할 때: '가게에 들어가기' → 사진(png) → '다음 ▶' → 태그 하나 → '다음 ▶' → 마음 가격 → '감정 받기!' → 답 풀기
  - 그러면:
    - ①에는 '가게에 들어가기'만 있고 사진 고르기 · 태그 · 가격은 없다
    - ②에는 사진 고르기만, ③에는 태그만, ④에는 마음 가격 · 리전 안내 · '감정 받기!'만 있다. 고르는 칸은 자기 단계에서만 보인다
    - ②에서 사진을 고르면 그 사진 미리보기가 보인다
    - ⑤에는 진행 막대가 있고 버튼이 0개이며, 숫자로 된 진행률은 없다(서버가 진행률을 주지 않음)
    - ⑥에는 아저씨 값 · 내가 부른 값 · 비교 한 줄 · 서버 대사(`line`) · '다른 물건 꺼내기'가 있고 고르는 칸은 없다
    - 주소는 모든 단계에서 `pathname === '/'` · `hash === ''`다
- AC-2 단계마다 필요한 것을 골라야 넘어가고, ③은 건너뛸 수 있다
  - 주어진: AC-1과 같은 화면 단위 테스트
  - 할 때: 경우마다 새로 시작해 ② · ③ · ④를 고르지 않은 채, 또는 고른 뒤에 본다
  - 그러면:
    - ②의 '다음 ▶'은 jpg · png를 고르기 전에는 꺼져 있다. 다른 파일을 고르면 꺼진 채 지금 문구('사진을 다시 골라 주세요 (jpg·png)')가 나온다
    - ③은 아무것도 안 고르고 '다음 ▶'을 눌러도 넘어가고, 이때 `appraise`의 `tags`는 `[]`다
    - ④의 '감정 받기!'는 가격을 고르기 전에는 꺼져 있다
    - 태그는 contracts §3 이름 그대로 16개 · 4묶음이고, 보내는 `tags`는 contracts 차례다
    - 고른 칩은 앞에 `▶`가 보이고 `aria-pressed="true"`다. 안 고른 칩은 `false`다
    - 칩 · 버튼은 화면에서 높이 24 CSS px 이상이다(WCAG 2.5.8 최소값. 44로 키울지는 A5)
- AC-3 서버 요청은 감정 1번에 1번이고 ④에서만 나간다 (Jira 한 줄 · 추천안 기준: Q2 · Q8)
  - 주어진: Playwright, 진짜 Bedrock을 부르지 않는 지금 e2e 방법, `POST /api/appraise` 요청 수를 센다
  - 할 때 / 그러면:
    - ①~④를 지나는 동안(③ 건너뛰기 포함) 0번
    - '감정 받기!'를 잇달아 2번 누르면 1번
    - ⑥에서 '다른 물건 꺼내기'를 누르면 그대로 1번이고, 다시 ④에서 '감정 받기!'를 누르면 2번
    - 실패 · 퇴근 화면의 버튼을 누르면 늘지 않고, ④에서 다시 누를 때만 1 늘어난다
    - '뒤로' · '앞으로' · 새로고침으로는 늘지 않는다
- AC-4 화면마다 맞는 아저씨 표정과 장면이 나온다
  - 주어진: 화면 단위 테스트. 그림이 어느 표정인지 테스트가 읽을 수 있다(표시 방법은 A1)
  - 할 때: 아래 표의 화면을 각각 띄운다(`appraise`는 해당 코드로 거부 · 코드 없음은 `unavailable`)
  - 그러면:

    | 화면 | 표정 | 장면 |
    |---|---|---|
    | ① · ⑥ | 웃음 | 나무 벽 · 선반 물건 4개 · 계산대 |
    | ② · ③ · ④ · busy · invalid_input | 기본 | 같음 |
    | ⑤ | 돋보기 | 같음 |
    | refused | 찡그림 | 같음 |
    | unavailable | 식은땀 | 같음 |
    | person_limit | 졸림 | 같음 |
    | daily_limit | **아저씨 없음** | 어두운 가게 · '오늘 영업 끝' 팻말 |
- AC-5 실패 · 퇴근 · 바쁨 문구는 지금 글자 그대로이고, 거기서 돌아갈 수 있다 (추천안 기준: Q2 · Q6 · Q8)
  - 주어진: 화면 단위 테스트, 사진 · 태그 · 가격을 고른 뒤 '감정 받기!'. 첫 감정에서 거부되는 경우와 앞 결과 뒤에 거부되는 경우 둘 다
  - 할 때 ①: `refused` · `unavailable` · `person_limit` · `daily_limit` · 코드 없음으로 거부된다
  - 그러면 ①: `options.js`의 `ERROR_TEXT` · `OFF_DUTY_TEXT`와 글자 그대로 같고(코드 없음은 `unavailable` 문구), 실패는 `role="alert"`이다. 앞 결과 카드는 없고 공유 버튼도 없다
  - 할 때 ②: 각 화면의 버튼을 누른다
  - 그러면 ②: refused는 ②로 간다. unavailable · person_limit · daily_limit · 코드 없음은 ④로 간다. 모두 고른 사진 · 태그 · 가격이 그대로다
  - 할 때 ③: `invalid_input`으로 거부된다
  - 그러면 ③: ②로 돌아가 `ERROR_TEXT.invalid_input` 문구가 보이고 고른 것은 그대로다. 다른 사진을 고르면 문구가 사라진다
  - 할 때 ④: 답을 붙잡아 둔 채 ⑤에서 '뒤로'를 누른다
  - 그러면 ④: ④에 '감정 받기!'가 꺼져 흐리게 보이고 `BUSY_TEXT`가 글자 그대로 나온다. 답이 오면 결과로 넘어가지 않고(CAREER-32 U10 b) 안내가 사라지며 버튼이 켜진다. **그때 눌러 다시 감정이 된다**(CAREER-32에서 비어 있던 테스트)
- AC-6 ⑥ 값 공개가 값과 비교 한 줄을 맞게 보여 준다 (Q1 · Q7)
  - 주어진: 화면 단위 테스트, 고른 값과 서버 값을 아래처럼 바꿔 가며
  - 할 때: 답이 온다
  - 그러면:
    - 아저씨 값 · 내가 부른 값이 가정 4 모양으로 보이고, 대사는 서버 `line` 그대로다
    - 비교 한 줄: 서버 값 > 내 값이면 '▲ 아저씨가 더 쳐줬다!'이고, 서버 값 < 내 값이면 '▼ 아저씨는 좀 짜게 봤다', 같으면 '= 자네 눈이 제법이군!', `never`이면 '안 판다니… 그래도 값은 매겨 봤네'다(Q7, 사용자 11/1). `mochi: 0`도 '작을 때'로 맞게 나온다
    - 추천안 기준(Q1 A): 답이 오면 ⑤에 더 머물지 않고 바로 ⑥이다. 실패 · 퇴근은 Q1과 상관없이 바로 나온다
- AC-7 '뒤로' · '앞으로' · 새로고침 · 바로 열기 (추천안 기준: Q2)
  - 주어진: Playwright, AC-3과 같은 방법, 처음 주소(`/`)
  - 할 때 / 그러면:
    - ④ → ③ → ② → ①로 '뒤로'를 누르면 한 단계씩 돌아가고 고른 것은 그대로다
    - ⑥과 실패 · 퇴근 화면에서 '뒤로'를 누르면 ④로 가고 고른 것은 그대로다
    - ⑥에서 '뒤로' 뒤 '앞으로'를 눌러도 앞 결과 카드는 다시 나오지 않는다
    - 감정을 3번 한 뒤 '뒤로'를 계속 눌러도 앞 결과 카드는 한 번도 나오지 않는다
    - ⑤ · ⑥ · 실패 · 퇴근 · ②~④에서 새로고침하거나 새 탭으로 열면 빈 ①이다
    - **새로고침 뒤 '뒤로' · '앞으로'를 눌러도** 사진 없는 ③ · ④나 앞 결과가 나오지 않는다(CAREER-32에서 비어 있던 테스트)
    - 사진 · 고른 것은 localStorage · sessionStorage · IndexedDB · 주소 어디에도 남지 않는다
- AC-8 화면 읽기 · 키보드로 6단계를 끝까지 갈 수 있다 (추천안 기준: Q3)
  - 주어진: 화면 단위 테스트
  - 할 때: 화면이 바뀔 때마다 `document.activeElement`와 접근성 이름을 본다. 처음 연 화면도 본다
  - 그러면:
    - 처음 열 때는 초점을 뺏지 않고, 화면이 바뀌면 초점이 `body`가 아니라 새 화면 안에 있다
    - 각 단계에 이름표가 있다(`물건 꺼내기`처럼 시안의 단계 이름)
    - ⑥ 초점은 '감정 결과' 영역, 실패는 `appraise-error`, 퇴근 · ⑤는 `role="status"` 칸이다(CAREER-32 그대로)
    - 도트 그림은 장식으로 처리하고, 표정의 뜻은 문구 · 이름표로 전해진다
    - ▶ · ▼ · `_`가 낱글자로 읽히지 않는다
    - 움직임이 있다면 `prefers-reduced-motion`에서 멈춘다
- AC-9 그림이 시안 지도와 한 칸도 다르지 않다 (Q4)
  - 주어진: `mockup-v3.html` 끝 `<script>`의 `U` · `I` · `PU` · `PI`
  - 할 때: 앱에 들어간 표정 6개 · 물건 4개를 지도와 맞대 본다(자동)
  - 그러면: 표정은 40×40, 물건은 12×10 또는 12×9이고 칸마다 색이 같다. 화면에서 칸 경계가 흐려지지 않는다(눈 확인은 AC-12)
- AC-10 글꼴이 사이트 안에서 온다
  - 주어진: Playwright, 페이지가 내는 모든 요청을 기록한다
  - 할 때: ①부터 ⑥까지 간다
  - 그러면:
    - 다른 도메인으로 가는 요청이 0개다(시안의 jsdelivr 링크가 따라오지 않음)
    - 글꼴 파일은 200으로 오고 화면 글자에 갈무리가 적용된다
    - OFL 라이선스 글이 빌드 결과에 함께 들어간다
    - 글꼴이 오기 전에도 글자가 보인다(비어 있지 않음)
- AC-11 화면을 내리지 않아도 보인다 (CAREER-32 AC-4를 이음)
  - 주어진: Playwright, 375×548(CAREER-32 plan A2 크기)
  - 할 때: 각 화면이 뜬 뒤 스크롤하지 않고 본다
  - 그러면:
    - `toBeInViewport({ ratio: 1 })`로 ①의 버튼 · ④의 가격 · 리전 안내 · '감정 받기!' · ⑤의 대사 · 막대 · ⑥의 값 영역 · '다른 물건 꺼내기'가 다 보인다
