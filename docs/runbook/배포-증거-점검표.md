# 배포 증거 점검표 (release-ops가 배포 뒤 채움)

> 출처: ECC skills/production-audit의 Evidence Checklist·Operations·User Experience (MIT, Affaan Mustafa)를 how-much에 맞게 줄임. README '동작 증거' 칸의 재료 — README는 사용자가 쓴다.

배포: YYYY-MM-DD · PR #N · CAREER-N

## 1. 싼 확인부터
- [ ] `git log --oneline -5` · 배포한 커밋 =
- [ ] CI 결과 링크 =
- [ ] terraform plan 요약(추가·변경·삭제) =

## 2. 돌아가나 (증거: 링크·화면·로그 한 줄씩)
- [ ] 깨끗한 checkout에서 적힌 명령으로 시작된다
- [ ] 필요한 환경변수 이름이 적혀 있고, 없으면 바로 실패한다
- [ ] 상태 확인(health)이 의존하는 것까지 닿는지 보여 준다
- [ ] 핵심 흐름(사진 → 감정 → 결과 카드)이 데스크톱·휴대폰에서 된다
- [ ] 로딩·빈 화면·오류·'퇴근'(하루 상한) 상태가 무슨 일인지 말해 준다
- [ ] 비용 상한이 실제로 걸린다(상한 낮춰 한 번 확인 → 되돌림)

## 3. 되돌리기와 로그
- [ ] 배포·되돌리기 방법이 런북에 있다
- [ ] 로그에 비밀값·개인정보가 없다
- [ ] 문제 생기면 누가 무엇을 하는지 적혀 있다
