## 0. 먼저 알아 둘 것 (경고)
- **`user_data`·AMI를 바꾸거나 서버를 교체하면 셈이 0이 된다.** 하루 셈 파일(`/home/howmuch/.local/state/how-much/usage.json`)은 서버 디스크에만 있다. 그래서 `aws_instance.web`에 `prevent_destroy`가 걸려 있다 — plan이 교체(`-/+`)를 만들면 CI가 오류로 멈춘다. 멈추면 그 PR을 고친다. `prevent_destroy`를 지워서 넘기지 않는다
- **v1을 내리려면 `prevent_destroy` 줄부터 지운다.** 그 줄을 지우는 PR을 먼저 머지해야 `terraform destroy`가 된다
- **`setup-host.sh`를 돌린 때부터 첫 배포가 끝날 때까지 v1 주소 `/`는 404다.** nginx가 `/opt/how-much/app/current`를 보는데 그 폴더는 첫 배포가 만든다. 그래서 서버 준비(§2)와 첫 배포(§3)는 **한자리에서 이어서** 한다
- `aws-infra-portfolio`는 **main에 머지하면 바로 apply**된다(그 저장소 `deploy.yml`). 머지 = 실제 변경이다
- 엔드포인트 요금(bedrock-runtime, 월 약 $7~10)은 PR #2 머지(2026-10-28 16:30)부터 나간다. 멈추는 법은 §7

## 1. 들어가는 법 (EC2 Instance Connect Endpoint)
서버에는 공인 IP가 없다. 22번 포트는 EIC 보안 그룹에서만 열린다(contracts §4).

- **서버 시계는 UTC다.** `journalctl --since`에 서울 시각을 넣으면 아직 오지 않은 시각이 되어 한 줄도 안 나온다 → UTC로 적거나(서울 09:13 = UTC 00:13) `--since '-15 min'`처럼 쓴다. 출력이 길면 `--no-pager`
- 한동안 입력이 없으면 접속이 끊긴다. 같은 명령으로 다시 들어오면 된다(서버 상태는 그대로)

```bash
export AWS_PROFILE=terraform-admin AWS_REGION=ap-northeast-2
export HM_INSTANCE=i-0f5ee0418d5252c9a        # aws-infra-portfolio 출력 web_instance_id

# 셸로 들어가기 (키는 CLI가 잠깐 만들어 밀어 넣는다)
aws ec2-instance-connect ssh --instance-id "$HM_INSTANCE" --connection-type eice --os-user ec2-user
```

파일을 보낼 때는 scp를 쓴다. 밀어 넣은 공개 키는 **60초만** 쓸 수 있으니 바로 이어서 돌린다.

```bash
[ -f ~/.ssh/hm-eic ] || ssh-keygen -q -t ed25519 -N '' -f ~/.ssh/hm-eic
aws ec2-instance-connect send-ssh-public-key --instance-id "$HM_INSTANCE" \
  --instance-os-user ec2-user --ssh-public-key file://$HOME/.ssh/hm-eic.pub --output text
scp -i ~/.ssh/hm-eic -o StrictHostKeyChecking=accept-new \
  -o ProxyCommand="aws ec2-instance-connect open-tunnel --instance-id $HM_INSTANCE --remote-port 22" \
  <보낼 파일> ec2-user@hm-web:<받을 자리>
```

- 들어갈 수 없으면(시간 초과·거절) **멈추고 묻는다**(plan 실패 시나리오 17). EIC가 안 되면 대안은 SSM이고, 그건 요금·IAM이 바뀌는 결정이다

## 2. 처음 한 번 — 서버 준비 (`setup-host.sh`)
§0 경고대로, 이 단계가 끝나면 바로 §3 첫 배포로 간다.

1. Mac에서 main 최신을 받고 `infra/deploy/`를 서버로 보낸다. **두 번째부터는 먼저 서버(§1로 들어가서)에서 `sudo rm -rf /var/tmp/how-much-setup`** — 폴더가 남아 있으면 `scp -r`이 그 안에 `deploy/`를 새로 만들고, 아래 4단계는 옛 스크립트를 오류 없이 다시 깐다

   ```bash
   cd /Users/admin/Documents/GitHub/how-much && git switch main && git pull --ff-only
   aws ec2-instance-connect send-ssh-public-key --instance-id "$HM_INSTANCE" \
     --instance-os-user ec2-user --ssh-public-key file://$HOME/.ssh/hm-eic.pub --output text
   scp -r -i ~/.ssh/hm-eic -o StrictHostKeyChecking=accept-new \
     -o ProxyCommand="aws ec2-instance-connect open-tunnel --instance-id $HM_INSTANCE --remote-port 22" \
     infra/deploy ec2-user@hm-web:/var/tmp/how-much-setup
   ```

2. §1로 들어가서 먼저 본다

   ```bash
   rpm -q ec2-instance-connect nginx; uname -m; sudo -n true && echo sudo-ok
   /usr/bin/node --version        # v22.x 여야 한다. 없으면 아래 3
   ```

3. Node 22가 없으면 꾸러미 저장소에서 받는다(S3 게이트웨이 엔드포인트 길 — 2026-10-29 됨: `nodejs22` 설치 시 alternatives가 `/usr/bin/node` → `node-22` 링크를 건다, v22.23.2)

   ```bash
   sudo dnf install -y nodejs22 && ls -l /usr/bin/node*
   ```

   `/usr/bin/node`가 22가 아니면(예: `node-22`만 생김) **멈추고 묻는다** — 단위 파일 `ExecStart`가 `/usr/bin/node`를 부른다

4. 준비 스크립트를 돌린다 (다시 돌려도 같은 결과)

   ```bash
   cd /var/tmp/how-much-setup && sudo bash setup-host.sh
   ```

   `nginx -t`가 실패하면 스크립트가 설정을 `how-much.conf.rejected`로 치우고 멈춘다(v1 nginx.conf에도 `default_server`가 있을 때 등). 그러면 출력을 붙여 들고 멈춘다

   `nginx: [warn] conflicting server name "_" on 0.0.0.0:80, ignored`는 **정상**이다 — v1 기본 server 블록과 이름이 겹칠 뿐, 요청은 `default_server`인 how-much 블록이 받는다(2026-10-29 확인: 첫 배포 전 `curl http://127.0.0.1/` → 404 = how-much 블록)

   `setup-host.sh` 마지막 `systemctl reload nginx`는 새 설정이 먹기 전에 돌아온다. **바로 뒤 시험은 옛 설정에 닿을 수 있다** → 몇 초 기다린 뒤 시험한다(2026-10-29: 바로 뒤 413·502, 몇 초 뒤 400·503)

5. 확인한다

   ```bash
   id howmuch; systemctl is-enabled how-much-api; node --version; sudo nginx -t
   ```

   → `howmuch` 사용자 · `enabled` · `v22.x` · `syntax is ok`

## 3. 배포하는 법 (GitHub Actions `deploy`)
늘 **main의 커밋 하나**를 올린다. 화면과 `api/`가 같은 sha다.

1. GitHub how-much → Actions → `deploy` → **Run workflow**(브랜치 main)
   - 또는 Mac에서: `gh workflow run deploy.yml --ref main -R culonculon/how-much`
2. `production` 환경 승인 요청이 오면 **사람이 승인**한다
3. 잡 요약에서 본다
   - `deployed <sha>`
   - `listening` 줄에 `"address":"127.0.0.1"` (8787은 같은 컴퓨터 안에서만)
   - `startup_failed` 줄이 **없다**(인스턴스 역할로 자격 증명이 풀림)
   - `CloudFront 무효화: <id>`
4. 서버 안에서 한 번 더 (§1로 들어가서)

   ```bash
   sudo journalctl -u how-much-api -o cat | tail -3
   systemctl show how-much-api -p User -p DynamicUser -p ProtectHome
   ```

   → 마지막 `appraise` 줄 `outcome invalid_input` · `reason bad_my_price` · `attempts 0`(확인용 요청 — Bedrock 0) · `User=howmuch` · `DynamicUser=no` · `ProtectHome=no`
5. 밖에서: `curl -s https://d2x05xzjhjvp9j.cloudfront.net/ | grep -c '<div id="root"'` → `1`

- 배포는 확인용으로 서버 안에서 `POST /api/appraise`를 1번 보낸다 → 로그에 `invalid_input` · `bad_my_price` · **`who:"none"`** 줄이 1줄 생긴다(CloudFront를 거치지 않아 주소 헤더가 없음). 밖에서 온 요청에는 CloudFront가 늘 헤더를 붙이므로, `who` none/bad를 셀 때는 이 줄을 뺀다
- 터널은 `--max-tunnel-duration 3600`을 넘긴다 — 배포 역할 `OpenTunnel` 조건 `maxTunnelDuration ≤ 3600`은 값이 없으면 맞지 않는다(2026-10-29 첫 실행 `AccessDeniedException`, PR #18)
- 서버 쪽 `install-release.sh`는 재시작 뒤 확인 셋(`listening` 줄 · POST 400 · GET 200)이 실패하면 **스스로 앞 판으로 돌아가고** 실패한 판 폴더를 지운 뒤 실패로 끝난다. 첫 배포는 앞 판이 없어서 그대로 실패로 끝난다 → 출력을 들고 멈춘다
- 두 배포가 겹치지 않는다(워크플로 `concurrency` + 서버 `flock`)

## 4. 되돌리는 법
### 4-1. 서버 코드 — 바로 앞 판으로

```bash
sudo /opt/how-much/bin/install-release.sh --rollback
```

- 화면·`api/` 링크 둘을 앞 판으로 바꾸고 재시작·확인한다. 판은 최근 3개까지 남는다
- 연달아 두 번 돌리면 원래 판으로 돌아온다(가장 최근에 푼 다른 판으로 가기 때문)
- **되돌린 뒤 확인도 실패하면** 스크립트가 원래 판으로 돌려놓고 실패로 끝난다. 그때는:
  1. 문제의 main 커밋을 **Revert**하는 PR을 열고 머지한다(how-much main은 PR로만)
  2. §3으로 그 main을 다시 배포한다
  3. 그 사이 서버가 위험하면 §6-1로 먼저 멈춘다

### 4-2. 인프라 — 머지한 PR을 Revert
`aws-infra-portfolio`에서 그 PR의 **Revert PR**을 열고 plan을 읽은 뒤 머지한다(머지 = apply).
- plan에 `aws_instance.web` 교체(`-/+`)가 보이면 머지하지 않는다(§0)
- `bootstrap/`(배포 역할)은 CI 밖이다 — 원래 폴더 `bootstrap/`에서 로컬 `terraform plan` → 읽고 → `apply`

## 5. 로그 읽는 법 (journald)
서버는 한 요청에 1줄씩 표준 출력에 쓰고 journald가 받는다(`Storage=persistent` · 최대 200M). nginx `/api/` 접속 로그는 꺼져 있다(주소를 남기지 않음).

```bash
sudo journalctl -u how-much-api -o cat --since '2026-10-29 00:00'      # 시각부터 — UTC로 적는다(이 예 = 서울 09:00, §1)
sudo journalctl -u how-much-api -o cat --since '-30 min' | grep '"evt":"appraise"'
sudo journalctl -u how-much-api -o cat -f                              # 따라 보기 (Ctrl-C)
```

- 볼 칸: `outcome`(`ok` · `invalid_input` · `person_limit` · `daily_limit` · `unavailable` …) · `reason` · `attempts`(Bedrock 시도 수) · `dayUsed` · `who`(`ip4`·`ip6`·`none`·`bad`)
- `who`가 `none`이 계속 나오면 CloudFront나 nginx가 `CloudFront-Viewer-Address`를 넘기지 않는 것이다 — 모두가 한 사람으로 묶인다(plan 실패 시나리오 3)

## 6. 급히 막는 법 (빠른 것부터)
### 6-1. 서버를 멈춘다 — 몇 초

```bash
sudo systemctl stop how-much-api
```

- 감정 요청은 nginx가 JSON 503 `{"code":"unavailable"}`로 답한다. 화면은 그대로 뜬다. Bedrock 0
- 다시 켜기: `sudo systemctl start how-much-api` (재부팅하면 다시 켜진다 — `enabled`)

### 6-2. 하루 상한을 0으로 — 배포 한 번

`api/src/config.js`의 `DAILY_CALL_LIMIT = 300`을 `0`으로 바꾸는 PR → 머지 → §3 배포. 아저씨가 바로 🚶퇴근이다. 되돌릴 때는 같은 길로 `300`

### 6-3. 공개를 거둔다 — PR-C(#5) Revert
`aws-infra-portfolio`에서 PR #5(CloudFront `/api/*`, 2026-10-29 09:13 머지)의 Revert PR을 머지한다. 밖에서 `/api/*`로 오는 요청이 서버에 닿지 않는다. 화면은 남지만 감정은 실패 화면이 된다

## 8. 하루 상한 확인 (AC-7 (a)) — 서버 안에서
셈 파일 모양은 `{"day":"YYYY-MM-DD","used":N}` 한 줄이다. 서버는 감정마다 파일을 다시 읽으므로 **재시작이 필요 없다**. 서버와 같은 법(임시 파일에 쓰고 `mv`)으로 바꾼다(ADR-0004).

```bash
f=/home/howmuch/.local/state/how-much/usage.json
today=$(TZ=Asia/Seoul date +%F)
sudo -u howmuch cat "$f"                       # ① 지금 값을 적어 둔다 (예: {"day":"2026-10-29","used":4})

# ② used를 300으로
printf '{"day":"%s","used":300}\n' "$today" | sudo -u howmuch tee "$f.manual" >/dev/null
sudo -u howmuch chmod 600 "$f.manual" && sudo -u howmuch mv -f "$f.manual" "$f"

# ③ 새 사진으로 감정 → 🚶퇴근 · 로그 outcome daily_limit · attempts 0

# ④ 적어 둔 값으로 되돌린다 (적어 둔 day가 오늘이 아니었으면 used 0)
printf '{"day":"%s","used":%s}\n' "$today" <적어 둔 used> | sudo -u howmuch tee "$f.manual" >/dev/null
sudo -u howmuch chmod 600 "$f.manual" && sudo -u howmuch mv -f "$f.manual" "$f"

# ⑤ 코드의 상한이 그대로인지
grep -n 'DAILY_CALL_LIMIT =' /opt/how-much/api/current/src/config.js   # → 300
```

- 서버가 쓰는 임시 이름(`usage.json.tmp`)과 겹치지 않게 `.manual`을 쓴다
- 파일·폴더 권한 확인: `sudo stat -c '%U %a %n' /home/howmuch/.local/state/how-much "$f"` → `howmuch 700` · `howmuch 600`
