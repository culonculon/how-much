# 로컬 실행

> 기준: PR #6 (CAREER-24 앱 뼈대) 머지 뒤 `main`. 명령의 원본은 `pipeline.config.json`의 `checks.app`, 스크립트의 원본은 `app/package.json`.
> 확인: 2026-10-20 Node v22.18.0 · macOS에서 아래 명령을 실제로 돌렸다. CI는 `lts/*` Node를 쓴다.

## 인프라 변경: 없음
이 변경은 `app/`만 건드린다. Terraform 변경이 없어서 **apply 확인 목록(plan 요약 · 되돌리는 법)은 필요 없다.** 배포 절차도 아직 없다.

## 1. 설치
저장소 루트에서:
```
npm --prefix app ci
```
- `npm install`이 아니라 `npm ci`다. lock(`app/package-lock.json`)대로만 깔고 lock을 고치지 않는다. CI도 lock이 있으면 `npm ci`를 쓴다.

## 2. dev 서버
```
npm --prefix app run dev
```
- 뜨면 `http://localhost:5173/`. (Vite 기본 포트, 이미 쓰는 중이면 다음 번호로 뜬다.) 끝낼 때 `Ctrl+C`.
- 만든 결과를 미리 보려면 `npm --prefix app run build` 뒤 `npm --prefix app run preview`.

## 3. 검사 (끝내기 전에 이 순서로)
| 무엇 | 명령 | 통과 모습 |
|---|---|---|
| lint | `npm --prefix app run lint` | 출력 없이 끝남 |
| test | `npm --prefix app test` | `Test Files 1 passed`, `Tests 1 passed` |
| build | `npm --prefix app run build` | `✓ built in …ms`, `app/dist/` 생성 |
| e2e | (아직 없음 — `checks.app.e2e`가 `TODO`) | — |

테스트 수는 앞으로 늘어난다. 실패 없이 끝나는 것이 기준이다.

## 4. 흔한 실패와 되돌리는 법
| 증상 | 원인 | 하는 일 |
|---|---|---|
| CI의 `npm ci`가 `@rolldown/binding-linux-x64-gnu`를 못 찾는다고 실패 | lock을 맥에서 `npm install`로 고치면 다른 OS용 선택 설치 항목이 빠질 수 있다(npm의 알려진 동작). CI 러너는 linux | 아래 "lock 다시 만들기". lock은 `app_config` 구역이라 **frontend-dev가 PR로** 고친다 |
| `npm ci`가 "package.json과 lock이 안 맞는다"며 실패 | `package.json`만 고치고 lock을 같이 안 올림 | 같은 PR에 lock도 올린다 (frontend-dev) |
| dev 서버나 테스트가 이상하게 깨짐, 설치 중 끊김 | 깔다 만 `node_modules`, 낡은 `dist` | `rm -rf app/node_modules app/dist && npm --prefix app ci` (둘 다 git에 안 올라가는 폴더라 지워도 된다) |
| Node 버전 때문에 설치·실행 실패 | 낡은 Node | Node 22.13 이상(또는 24 이상)으로 맞춘다. 근거: 설치된 vitest 5의 `engines` `^22.12.0 \|\| ^24.0.0 \|\| >=26.0.0`, eslint 10의 `^22.13.0`. 이 저장소의 `.nvmrc`·`engines`는 아직 없다 |
| 포트 5173 사용 중 | 다른 dev 서버가 떠 있음 | 그 서버를 끄거나 뜬 다른 포트 주소를 쓴다 |

### lock 다시 만들기 (frontend-dev)
```
rm -rf app/node_modules app/package-lock.json
npm --prefix app install
```
- 확인: `grep -c "binding-linux-x64-gnu" app/package-lock.json`이 0보다 커야 한다. 지금 main의 lock에는 linux(x64·arm64, gnu·musl)·darwin·win32용 항목이 모두 있다.
- 그 뒤 위 3번 검사를 다시 돌리고 PR로 낸다.

### 변경을 되돌리기
- 이미 머지된 변경은 사용자가 머지 화면에서 해당 PR의 **Revert**로 되돌린다. main에 직접 push·강제 push는 하지 않는다.
- 로컬 작업만 버리려면: 브랜치를 지우거나 `git restore <파일>`. 새로 만든 폴더는 `git status`로 보고 지운다.

## 5. 이 문서가 확인하지 못한 것
- 맨 위 첫 번째 행(CI linux 실패)은 **재현하지 않았다.** lock에 linux 항목이 있음만 확인했고, 실패 모양은 npm의 알려진 동작 설명이다. 실제로 겪으면 에러 문구를 여기에 맞춰 고친다.
- CI 러너(linux)에서의 실행은 이 세션에서 보지 못했다. PR의 CI 결과가 증거다.
- Windows·Linux 로컬 실행은 돌려 보지 않았다.
