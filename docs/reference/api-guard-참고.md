# api/guard 참고 — 비용 상한·남용 막기 (함께 쓸 때 읽는 메모)

> 출처: ECC skills/cost-aware-llm-pipeline · agent-security-hardening (MIT, Affaan Mustafa). 2026-10-20 사용자 결정으로 가져옴. **값(상한·횟수·크기)은 여기서 정하지 않는다 — 함께 쓸 때 사용자가 정한다.** ECC 가격표는 빠르게 낡아서 뺐다.

## 1. 좁은 재시도
- 다시 시도: 연결 끊김 · 요청 수 초과(429/Throttling) · 서버 오류(5xx) 같은 **일시 오류만**
- 바로 실패: 권한 오류 · 잘못된 요청(4xx 검증 오류) — 다시 해도 돈만 쓴다
- 횟수 상한 + 지수 대기(1·2·4초…). 마지막에도 실패하면 오류를 그대로 올린다(삼키지 않는다)

## 2. 예산 넘으면 멈춤
- 호출 전에 '지금까지 쓴 비용 + 이번 예상 비용'이 상한을 넘는지 먼저 본다 → 넘으면 호출하지 않는다(아저씨 '퇴근' 상태)
- 비용 기록은 고치지 않고 덧붙이기만 한다(나중에 따져 보기 쉬움)
- 비용 조회가 실패하면 **0원으로 보고 통과시키지 않는다** — 막는 쪽으로 실패(fail closed)
- 모델 이름·상한은 코드 곳곳에 박지 않고 설정 한 곳에

## 3. 신뢰 경계 지도
- 경계마다 한 줄: `들어온 곳 → 해석 → 검증 → 실제 동작`
  - 예: 사진 업로드 → 형식·크기 확인 → 요청 수 확인 → 예산 확인 → AI 감정 호출(과금)
- 실제 동작마다 적는다: 누가 허락하나 · 바로 앞의 검증 · 입력·출력 최대 크기 · 남는 증거(로그) · 끊기면 되돌리는 길
- 모델 출력·사연 태그·사진 속 글자도 **믿지 않는 입력**으로 본다

## 4. AI 출력 제한
- 출력은 길이 상한을 두고 읽는다. 넘으면 자르고 '잘림 + 원래 크기' 표시
- 정해진 형식(예: `{ mochi: 숫자, line: 문자열 }`)이 아니면 빈 성공으로 바꾸지 않고, 어떤 경계에서 왜 실패했는지 이름 붙인 오류로 돌려준다
- 테스트: 너무 긴 출력 · 깨진 형식 · 정상 응답이 각각 정해진 결과를 내는지

## 5. 확인 관문 (끝났다고 하기 전에 실제 입구로 확인)
- 사용자 입력 속 지시문이 호출·쓰기를 일으키지 못한다
- 예산을 넘긴 요청은 과금 흔적을 남기지 않는다
- 너무 큰 입력·깨진 출력은 정해진 오류로 끝난다
- 실패해도 비밀값이 로그·임시 파일에 남지 않는다
