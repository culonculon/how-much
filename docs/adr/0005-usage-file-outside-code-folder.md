# ADR-0005: 하루 셈 파일은 코드 폴더 밖, 서버를 돌리는 사용자의 홈 아래 `~/.local/state/how-much/usage.json`에 둔다

- 날짜: 2026-10-24
- 상태: 확정 (2026-10-24 — 사용자 승인, CAREER-31 plan D3·D9)
- 정한 사람: 함께 (architect가 제안, 10/24 사용자가 고름)
- Refs: CAREER-31
- 대체하는 것: [ADR-0004](0004-daily-call-count-in-one-json-file.md)의 **자리**(`api/var/usage.json`)만. 모양·동기 읽고 쓰기·원자적 이름 바꾸기·막는 쪽 실패는 ADR-0004 그대로

## 상황
ADR-0004는 하루 Bedrock 셈을 `api/var/usage.json`에 두었다. 배포가 `api/` 코드 폴더를 새로 풀어 넣으면 `var/`도 새로 생겨 그날 셈이 0이 되고, 그날 상한 300이 한 번 더 생긴다(ADR-0004 '위험과 대비' 첫 줄). 밖에 열기(CAREER-30) 전에 이 구멍을 막아야 하는데, 배포 방식(복사·압축 풀기·컨테이너 등)은 CAREER-30에서 정해서 아직 모른다. 그래서 배포 방식에 기대지 않는 자리, 그리고 로컬과 EC2에서 같은 설정 한 줄로 정해지는 자리가 필요하다(spec AC-6 '설정 한 곳').

## 결정
`api/src/config.js`의 `USAGE_FILE`을 `join(os.homedir(), '.local', 'state', 'how-much', 'usage.json')`로 한다. 환경변수로 바꾸지 않는다. 처음 만들 때 폴더는 `0700`, 파일은 `0600`이다. 홈이 없거나 쓸 수 없으면 지금처럼 `unavailable`이다(ADR-0004 U10).

## 버린 대안
### 대안 1: 환경변수로 받는 경로 (`HOW_MUCH_USAGE_FILE`, 없으면 `api/var/`)
- 좋은 점: 배포마다 자리를 고를 수 있다. 로컬은 지금 그대로
- 나쁜 점: 배포에서 변수를 빠뜨리면 조용히 코드 폴더 안(0)에서 시작한다 — 막으려던 구멍 그대로. 값이 정해지는 곳이 둘(기본값·환경)이 된다
- 왜 아님: ADR-0004 대안 5와 같은 이유. '빠뜨리면 조용히 상한이 새로 생김'이 이 결정이 막으려는 바로 그 실패다

### 대안 2: systemd `StateDirectory=` (`/var/lib/how-much`, 서버는 `STATE_DIRECTORY` 환경변수로 받음)
- 좋은 점: 리눅스 서비스의 표준 자리이고 권한·소유를 systemd가 맞춘다
- 나쁜 점: 로컬(macOS)에는 없다 — 로컬은 다른 자리가 되어 설정이 둘. 배포가 systemd라는 가정을 CAREER-30 전에 박는다
- 왜 아님: 배포 방식이 아직 안 정해졌다. CAREER-30이 systemd를 고르더라도 서비스 사용자에게 홈을 주면 이 결정이 그대로 돈다

### 대안 3: 절대 경로 고정 (`/var/lib/how-much/usage.json`)
- 좋은 점: 눈에 잘 띄는 자리, 사용자와 상관없다
- 나쁜 점: 로컬에서 그 폴더를 만들려면 관리자 권한이 필요하다. 로컬과 배포가 같은 줄이 되려면 모든 개발 컴퓨터에 그 폴더가 있어야 한다
- 왜 아님: 로컬 첫 실행이 `unavailable`이 된다

### 대안 4: 코드 폴더 옆(`api/../how-much-state/`)
- 좋은 점: 홈을 쓰지 않는다
- 나쁜 점: 배포가 `releases/<판>/api`처럼 판마다 폴더를 만들면 '옆'도 판마다 바뀐다. 로컬에서는 저장소 안이라 루트 `.gitignore`(사용자 구역)를 고쳐야 한다
- 왜 아님: 배포 방식에 기댄다 — 상황의 조건을 못 지킨다

## 결과
### 좋아지는 것
- 코드 폴더를 어떻게 바꿔 넣어도 그날 셈이 이어진다(서비스 사용자의 홈이 남는 한)
- 로컬·EC2가 같은 한 줄. 환경변수 없음 — 빠뜨려서 생기는 조용한 실패가 없다
- 같은 컴퓨터의 다른 사용자는 셈을 읽거나 고치지 못한다(`0700`/`0600`)

### 나빠지는 것
- 로컬에서 worktree 여러 개와 시험 실행이 **셈 하나를 나눠 쓴다**(ADR-0004에서는 worktree마다 따로). '이 컴퓨터가 하루에 쓰는 돈'이라는 뜻에는 더 맞지만, 다른 worktree에서 많이 쓰면 이 worktree의 dev 서버도 퇴근한다
- 셈이 저장소 밖, 눈에 덜 띄는 곳에 있다
- 지금 있는 `api/var/usage.json`은 버려진다 — 로컬 셈이 한 번 0에서 다시 시작한다(로컬뿐이라 받아들임)

### 위험과 대비
- **EC2 서비스 사용자에게 홈이 없거나, 다시 배포할 때 홈이 지워짐**(systemd `DynamicUser=`·`ProtectHome=`, 컨테이너의 쓰고 버리는 파일 시스템) → 없으면 `unavailable`로 크게 드러나고, 지워지면 ADR-0004 위험과 같은 0이 된다. CAREER-30 완료 조건에 '서비스 사용자의 홈이 다시 배포해도 남고 쓸 수 있다'를 넣도록 제안한다(CAREER-31 plan '범위 밖')
- 테스트가 진짜 자리를 건드림 → 테스트는 `tempDailyLimit()`만 쓰고, AC-6 테스트는 `HOME`을 그 파일 안에서만 임시 폴더로 바꾼다. CAREER-31 G4 검사가 테스트 앞뒤로 진짜 파일의 수정 시각이 같은지 본다
- 서버가 여러 대가 되면 → ADR-0004 대안 6(DB)으로 이 ADR과 0004를 함께 대체한다
