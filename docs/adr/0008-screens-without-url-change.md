# ADR-0008: 화면 3단(입력 → 갸웃 → 결과)은 주소를 바꾸지 않고, 라우터 없이 history 항목 한 칸으로 바꾼다

- 날짜: 2026-10-30
- 상태: 확정 (2026-10-31)
- 정한 사람: architect 제안 — 사용자 승인 대기 (CAREER-32 plan A1)
- Refs: CAREER-32

## 상황
CAREER-32에서 화면이 입력 → 갸웃 → 결과 셋으로 나뉜다. 브라우저 '뒤로'는 결과에서 입력으로 가야 하고, '앞으로'로 옛 결과가 다시 나오면 안 되며, 새로고침·바로 열기는 빈 입력 화면이어야 한다(spec AC-5 · 가정 5). 배포 nginx는 `try_files $uri $uri/ =404`라서 `/result` 같은 경로 주소는 새로고침하면 404가 난다. 로컬 Vite는 그렇지 않아 e2e로는 안 잡힌다. spec 가정 3은 `infra/`(nginx · CloudFront)를 바꾸지 않는다.

## 결정
주소는 언제나 `/` 그대로 둔다. '감정 받기'를 누를 때(클릭 처리 안에서, `await` 전에) 지금 history 항목이 우리 표시(`{ howMuch: 'out' }`)가 아니면 `history.pushState({ howMuch: 'out' }, '')`로 한 칸만 쌓는다. `popstate`가 오면 언제나 입력 화면으로 가고 그때 가던 요청의 답은 버린다. 라우터 라이브러리는 쓰지 않는다.

## 버린 대안
### 대안 1: 라우터 라이브러리(react-router 등)
- 좋은 점: 화면이 늘면 경로 표가 한 곳에 모인다. 익숙한 방식이다
- 나쁜 점: 새 의존성. 경로 주소(`BrowserRouter`)는 nginx 404 → `infra/` 변경. `HashRouter`라도 '앞으로'로 옛 결과를 막고 바로 열기를 빈 화면으로 돌리는 코드는 따로 써야 한다
- 왜 아님: 화면 셋 · 주소 하나인 지금, 라이브러리가 해 주는 일(주소 ↔ 화면 맞추기)이 바로 우리가 막아야 하는 일이다

### 대안 2: 화면마다 `#` 주소(`/#thinking` · `/#result`)
- 좋은 점: nginx를 안 바꾼다(`#` 뒤는 서버로 가지 않음). 주소만 보고 어느 화면인지 안다
- 나쁜 점: 첫 화면에서 `#result`를 지우는 코드가 따로 든다(바로 열기 · 새로고침 = 빈 입력). 결과를 남에게 보낼 수 있는 주소처럼 보이지만 열면 빈 화면이다(공유는 11/8 뒤 공유 카드 몫)
- 왜 아님: 주소가 하는 일이 없는데 지울 일만 는다

### 대안 3: 경로 주소(`/result`) + nginx `try_files … /index.html`
- 좋은 점: 주소가 읽기 쉽다
- 나쁜 점: `infra/` 변경(함께 하는 구역 · 가정 3 어긋남). 없는 주소가 모두 200이 되어 404가 사라진다
- 왜 아님: spec 가정 3

### 대안 4: history를 쓰지 않음(React 상태만)
- 좋은 점: 코드가 가장 적다
- 나쁜 점: 결과 화면에서 '뒤로'를 누르면 앱 밖(앞 페이지)으로 나간다
- 왜 아님: spec AC-5 ①

## 결과
### 좋아지는 것
- `infra/` · nginx · CloudFront를 바꾸지 않는다. 어느 화면에서 새로고침해도 서버는 `/`만 받는다
- 새 의존성 0. history는 아무리 다시 감정해도 앱 몫이 두 칸(입력 · 그 위 한 칸)을 넘지 않는다
### 나빠지는 것
- 주소로 화면을 열 수 없다(결과 · 갸웃 바로 열기 = 빈 입력). 11/8 뒤 공유 카드가 주소를 쓰려면 이 ADR을 대체해야 하고, 경로 주소면 nginx도 함께 바꿔야 한다
- '다시 감정'으로 입력에 온 뒤 '뒤로'를 한 번 누르면 겉으로 아무것도 안 바뀐다(위 칸 → 아래 칸 모두 입력). 한 번 더 누르면 앱을 떠난다
### 위험과 대비
- **누군가 화면에 경로 주소를 더함** → 로컬은 되고 배포에서만 404. CAREER-32 e2e가 모든 화면에서 `pathname === '/'` · `hash === ''`를 확인해 로컬에서 빨강이 난다
- **`pushState`를 `await` 뒤에 부름** → 사용자 동작 없이 쌓인 항목은 Chrome이 '뒤로'에서 건너뛸 수 있다 → 결과에서 '뒤로'가 앱을 떠남. 클릭 처리 안에서 바로 부르고, AC-5 ① e2e가 잡는다
- **늦게 온 답을 버리지 않음** → 입력 화면에 옛 결과가 덮인다. 요청 번호(ref)로 버리고 AC-5 ⑤가 잡는다
