## 알려진 빈 곳 (reviewer · CI · 브랜치 규칙이 받친다)
- Bash로 쓴 파일은 ③이 못 막는다 → ⑥이 끝낼 때 git status로 잡아 돌려보낸다
- ⑥은 세션 시작 뒤 바뀐 미커밋 변경만 본다(10/20 고침 — CAREER-24 T1에서 남의 spec 파일 때문에 test-writer가 9번 돌려보내짐)
- Claude Code 자체도 Stop 훅이 계속 막으면 일정 횟수 뒤 끝낸다("통과할 때까지"의 실제 상한)
- `git -C 다른폴더 push`는 ②가 현재 폴더 브랜치로 판단한다
- 역할 frontmatter의 hooks는 `--agent`에서도 돈다(시험 운행 확인). `skills:`는 `--agent`에서 안 실린다(10/21 세션 기록 16개 + 시험) → ⑧이 넣는다
- ponytail 플러그인 SessionStart는 agent_type을 안 봐서 settings env `PONYTAIL_DEFAULT_MODE=off`로 끄고 ⑧이 만드는 역할에만 넣는다(10/21)
- ⑥은 Bash로 만들고 커밋까지 한 파일도 본다(10/21 — 시험 운행에서 커밋하고 끝내면 검사가 없던 문제). main을 받은 merge 커밋은 빼서 남의 변경을 구역 밖으로 오인하지 않는다
